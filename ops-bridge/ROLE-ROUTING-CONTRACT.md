# Nuvexa Telegram → WhatsApp 唯一角色分配规则

生效范围：Nuvexa Pro Cloud Edition 智能转发项目。本文件不改变其他独立产品。

## 1. 唯一消息格式

必须**严格三行**，无空行、前后缀或第四行。第三行须为人工已准备好的罗马尼亚语；程序不使用翻译 API，也不从中文推测译文。

    45老男：
    早上好.............
    Bună dimineața! Astăzi urmărim evoluția pieței.

第一行必须采用全角中文冒号 \`：\`：
- **助理：**、**教授：**：分别分配 ASSISTANT / PROFESSOR，使用对应已授权的主号（主号不在线时按既定专属备用规则处理）。
- **默认编制（可修改）：** 01–10 老女（10），11–30 新女（20），31–50 老男（20），51–65 新男（15），共65个普通成员角色。另有普通备用1/2/3、助理2号专属备用、教授2号专属备用，共5个备用角色；另有助理1号和教授1号两个主号，总计72个预置账号位置。
- **可修改配置：** 人物编码与身份在账号管理页分别编辑，并保存在后台；编码采用两位数字01–99，身份只能为“老女/新女/老男/新男”之一。必须保持编码唯一。系统不根据编号区间锁定身份，实际收到的 `编码+身份：` 必须与该编号当前配置相同；例如将45改为“新女”，则 `45新女：` 有效，旧的 `45老男：` 应拒绝。
- 旧格式 `45男`、`辅助45`、`45老男:`、`资讯助理` 等仍不受理。每条消息结构仍须严格三行，原文和罗马尼亚语分行填写。
- 第二行必须包含中文字符；第三行不能含汉字及中日韩标点，并须含拉丁字母。**这只检查结构与文字类型，不宣称机器验证罗马尼亚语语义正确性。**
- 角色前缀只是“任务路由标识”，不能证明 Telegram 发言人真实身份；系统仍需限制来源群及获授权的发布者。

## 2. 唯一发送账号

- 消息示例的编号 45 路由到分配给 code=45 的**唯一主 WhatsApp 发送账号**，不按 Telegram 显示名猜测账号。
- 一个已授权的 WhatsApp 发送号可服务多个明确配置的编号，但**每个编号只能指定一个主发送号**；出现重复映射应拒绝保存并阻止派发。
- 未配置主发送账号或出现重复映射：停止任务，不可用随机备用号顶替。
- 助理和教授使用各自独立专属备用。普通成员主号确认为不可发送后，才使用共享备用 1 → 2 → 3。结果未知不盲目重发。
- 默认65个普通角色位置不等于65个已登录 WhatsApp 账号。编号支持01–99，但必须在管理后台明确绑定真实授权账号和身份，未绑定即拒绝派发。
- 用户编辑人物编号时，旧主编码关联应撤销，已授权 WhatsApp 会话和发送账号本身保持不变；三个普通备用不得冒充专属助理/教授备用。

## 3. 内容及完成判定

- Telegram 来源群 → 格式校验 → 角色唯一映射 → 实时账号状态核验 → 已启用的 WhatsApp 目标群组 → 平台发送确认。
- 仅发送第三行罗马尼亚语，不发送第二行中文；如附有图片，仅临时传输实际图片，原始图片不进行文字扫描/翻译。
- Worker 回执必须能够核对**实际发送账号 ID + 实际群组 ID + 真实 WhatsApp 消息 ID + 服务器/设备 ACK**。未经确认留在待核实状态，不报告成功。
- 消息和临时任务在全部目标群组结果完成后清理，不保存聊天文本/图片/长期转发明细。短时去重哈希标记最多保留 1 小时，避免 Telegram 重发导致重复投递。
- **保留配置**：账号与授权 Session、角色绑定、目标群组、必要的运行状态；这些不是聊天历史。

## 4. 明确移出本项目

**不提供、不开启、也不开发**以下功能：
- WhatsApp 群成员进群/退群事件监控；
- 群成员在线/离线监控；
- “15 天群成员监控记录”、15 天查询明细及自动清理任务。

注：账号本身的在线/离线绿点是发送设备健康状态，**并非监控 WhatsApp 群成员**，仍然保留。

## 5. 交付标准

先通过严格格式、唯一编号映射、拒绝错误格式和隔离单元测试，再使用经过授权的实际 Telegram 来源群及 WhatsApp 账号做端到端验收。上线前需用户独立确认；不修改主域名、现有生产后端数据或其他项目。
