# Nuvexa Ops｜7个真实WhatsApp账号分组轮换执行规范（待实现）

## 用户确定的运行方式
用户提前提供**需要转发的信息的角色发言顺序**。系统按消息的真实顺序进行派发，对应到后台已授权的 WhatsApp 真实发送账号，限制在**同时最多7个活动WhatsApp Web会话**。
该功能是研发需求，不代表现有Windows连接器已支持动态切换或真实消息发送。

## 准备输入
- 只接受角色序列，例如：助理 → 45老男 → 12新女 → 教授 → 51新男 → 45老男 → …；
- 编码和身份须按后台最新配置验证；必须来自获授权来源和真实发件账号；同一个真实WhatsApp账号可承担多个编码。
- 严格三行原文消息格式，正文只发送第三行罗马尼亚语。
- 每一轮的目标WhatsApp群组由后台已启用群组配置决定。
- 发言顺序与账号轮换是两件事：**顺序按Telegram原始任务固定，活动窗口只管理最多7个不同的实体账号**。同一账号重复出现时在当前窗口复用，不能重复占用名额。

## 建议状态机
1. PLAN：管理员设定发言顺序；检查每个编号与人物身份、真实账号归属，检查目标群组及必要的备用账号预先授权；生成待执行窗口；不登录任何未授权账号。
2. WARMUP：逐个/限流恢复最多7个本地会话，不同时启动7个Chromium导致CPU峰值；确认ready+getState CONNECTED的实测状态；启动失败标 NEEDS_QR/OFFLINE/UNKNOWN，不假在线。
3. ACTIVE：按照原始队列序号，派发到启用目标群组；**同一时刻只处理符合现有严格队列规则的任务**；发送成功必须校验实际发送账号、实际目标群组、消息ID及Provider ACK，不代表全部群成员已读。
4. DRAIN：当前活动窗口所有已派发任务及各目标群组都获得终态确认才准备切换。出现VERIFYING、发件结果不明时**冻结切换**，不能因为超时自动判成功或重发。
5. RELEASE：只销毁已完成账号的浏览器Client实例并清理运行内存；**不可执行 WhatsApp logout、不可删除 LocalAuth会话或授权配置**；发送账号状态区分“计划休眠”与“异常离线”，休眠不得显示为真实在线。
6. NEXT：待上个窗口释放资源、下个账号真正在线后继续处理下一队列项；历史内容完成即清理，保留必要的账号绑定/登录授权/群组配置以及短时去重。

## 备用账号规则
- 助理1只允许助理2专属备用，教授1只允许教授2专属备用；普通成员优先备用1→2→3。
- 只有已确认原发件账号无法发送/未发送，才允许准备备用账号。
- 如活动窗口7个名额占满，先安全释放确认已完成或不可用的会话，再加载备用；不要突破活动上限，也不能强制切走待验证任务。
- 备用账号**不必长期占据7个活动名额**；需要时按配置换入，且必须曾获账号持有人授权。

## 故障、重启、安全
- 正在处理的任务允许最小化短暂持久化用于安全恢复；已完成任务及消息正文、媒体引用立即清除。
- 断线/电脑重启后只恢复未完成工作与必要会话，不误判完成、不重复发布。
- 连接器仍是非官方WhatsApp Web方式，可能受客户端变更、平台限制或账号使用条款影响，不应保证绝对稳定。
- 当前Windows连接器默认maxActive=3，支持配置上限但**没有单账号关闭并释放名额的分组切换调度、没有实际发送Worker**，不应声称功能已上线。
- 先依次使用3、5、7活动会话进行真实性能验收，记录稳定运行、内存/CPU、登录恢复、断连、换组耗时、发送结果、失败不可重复发送，再确定7能否承受。

## UI/验收
- 界面需显示计划总数、当前批次、下一批次、活动账号（在线绿点）及计划休眠（灰色）、每个任务的已确认/待核实，不得伪造成功。
- 真正转发内容必须使用获授权账号，不能以虚构的独立投资人身份在财经群组营造虚假共识、回报或市场证据。
- 完整功能待实际发送端、单账号优雅关闭接口和调度器实现，且真实端到端验收通过后才可合并上线；不修改正式域名和生产数据。
