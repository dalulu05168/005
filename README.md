# 辰南撰写 · 人物与创作工作台

管理人物档案、群组、事件记忆、每日撰写、文档和模拟交易。浏览器通过 Supabase `workspace-cloud` 函数验证账号密码、恢复工作区和同步修改。默认人物资料是 `data/people.json` 中的 70 位虚构法国人物测试画像。

## 本地运行与检查

需要 Node.js 22 或更新版本。

```bash
npm ci
npm test
npm run test:gate
npm run build:static
npx playwright install --with-deps chromium webkit
npm run test:prelogin
python -m http.server 3000 --directory dist/pages
```

打开 `http://localhost:3000`。正常登录仍连接云端，不提供前端默认账号或管理员密码；登录后的隔离业务测试使用 CI 创建的临时账号，执行后清理。

## 登录与数据保存

账号密码在服务端验证，会话令牌保存在浏览器 `sessionStorage`，服务端只保存令牌哈希并支持退出撤销。没有本机密码认证。安全设置中确认密码后可绑定验证器；输入正确的6位验证码才会启用。启用后每次登录都需二次验证，服务端校验并阻止验证码重放。十个恢复码只展示一次、只存哈希，每个仅可用一次。绑定启用会撤销旧会话。更换验证器前请保存恢复码。

已加载的数据及编辑缓存保留在 `localStorage`。云端保存完成才显示同步成功；请求最长等待15秒。编辑先写入按账户隔离的本地待上传日志，失败自动退避重试，恢复网络后补传；页面隐藏或关闭前保存正在编辑的草稿。首次成功加载应用缓存后，同一浏览器已有会话可断网重开工作台。版本冲突保留独立恢复副本，点击顶栏“草稿待恢复”导出；不会覆盖另一设备的修改。清除浏览器数据、设备损毁或本地配额耗尽仍可能导致尚未上传的数据丢失。断网期间不能宣称云端已保存。

登录与开场固定使用黑金仙山主题，以用户提供的仙山楼阁、毛笔与比特币登录设计为准；不显示主题切换入口，旧查询参数和旧偏好不改变登录主题。登录后的工作台统一使用白灰 + 金色界面。分层场景约 2.6 秒渐显后，登录卡片从下方缓缓浮出；湖面纹理持续波动，毛笔轻摆，比特币沿立体轴旋转。可跳过开场；减少动态效果时快速显示并停止持续动画。认证层隐藏后释放场景渲染资源。记住账号只存账号名称，不保存密码。

## France 70 免费群聊

工作台新增“群聊引擎”模块，使用 `data/france70-v6.1.json` 的70位全量虚构人物、Voice DNA、作者正史和关系网。该模块不调用额外付费 AI API：先在网页中选择助理/教授内容并生成提示词，复制到用户现有 ChatGPT，随后将返回的 JSON 粘贴回工作台。系统会检查问句比例、分号和重复开头，并把完整会话快照与人物动态记忆保存到现有工作区，由原有 Supabase 云同步继续持久化。

真实性规则包括：直接问句目标 25–35%，牵引方式混合判断、条件、反驳、经验、回复与反应；质疑者和观望者无需被强制说服；执行/信随型人物只有在 Canon 或已保存动态事件支持时才可提到旅行、家庭生活改善等实际结果。

## 发布与自定义域名

Vercel 和 GitHub Pages 都发布 `dist/pages`。Vercel 构建参数由 `vercel.json` 管理；主分支提交经 Pages 工作流验证后自动同步到 `gh-pages`。Pages 应继续使用现有 `gh-pages` 根目录来源；CNAME 中保留已有 `nuvexapro.com`，本轮无需修改 DNS。

`release.json` 记录源码提交和完整静态文件哈希。发布完成后验证两个入口：

```bash
node scripts/verify-release.cjs https://nuvexapro.com/
node scripts/verify-release.cjs https://growth-story-workspace.vercel.app/
E2E_URL=https://nuvexapro.com/ npm run test:public-login
E2E_URL=https://growth-story-workspace.vercel.app/ npm run test:public-login
```

一处入口通过不代表另一处通过。若仓库禁止 Actions 写 `gh-pages`，需在仓库设置启用工作流写权限；若 Pages 未按分支更新，需核实 Pages 来源设置。未通过公网验证的提交不能宣称已正式上线。

当前验收要求见 [UI 与发布规范](docs/CODEX_UI_THEME_IMPLEMENTATION_SPEC.md)，历史修复记录见 [repair-notes](docs/repair-notes.md)。

## 人物与桌面视觉

人物显示编号为 C.01–C.70：01–10 老女、11–30 新女、31–50 老男、51–70 新男。原始主键保持不变，C 编号可检索、选择及在文档中插入，记录、持仓和分组关联不迁移。70 人使用独立虚构头像，并以文字标签与标识色区分分类。新头像为生成的虚构形象。

所有登录后业务模块统一使用白灰层次、黑色主文字与深金重点色；顶部“搜索/同步/管理员”整排不显示，页面直接从标题与主体开始。登录后左上品牌使用金色“辰南”毛笔字与蓝色细电流特效，不显示黑底图片或黄色圆环。持仓柱状图保持持有人数去重、排除已卖出和不同市场币种分开统计的语义。

登录背景提供本地 FSRCNN ×4 超分辨率重建后输出的 7680×4320 版本，以及 3840×2160 桌面版本。无需 Krea 点数；这是增强素材而非原生 8K 绘制。高分辨率屏幕按 GPU 纹理能力选择 8K，普通桌面加载 4K，低限额 GPU 自动缩小纹理。登录场景继续使用既有品牌素材；登录后的工作台品牌与业务页面视觉完全分离。工作台 Logo 居中位于导航上方，导航图标统一为同一套线性 SVG。桌面使用16:9工作区，左侧导航固定且不伸缩；业务长内容在主内容区内部滚动。


## 登录后统一设计系统

当前统一设计系统以“投资者人物总览”和“人物库”为唯一母版，覆盖全部十个一级模块与现有二级页面/弹窗流程。

- `design-system.css`：白灰背景、灰白1px边框、统一圆角、字体层级、按钮、输入框、表格、空状态、弹窗、一级工作台和人物详情页。
- `design-system.js`：统一一级 Header、同一套线性 SVG 导航图标、动态页面重新归一、ESC 返回二级页、动态内容监听。
- `tests/design-system.test.cjs`：防止后续页面重新漂移到另一套视觉。
- 分组固定为10个均衡小组，每组7人；当前70人结构精确为每组老女1、新女2、老男2、新男2。成员固定均衡，小组名称可修改。
- 人物详情页下半部分统一展示当前持仓、交易计划与推荐、联系记录，并保留完整持仓明细表。

现行 UI 验收标准以 `design-qa.md` 顶部“2026-10-03 当前统一 UI 验收基线”为准，旧深色工作台记录仅为历史。

## 人物成长与安全维护

人物记忆提示基于已保存的日期、原文、人物编号和规则：交易经历否认、首次事件、年龄变化、关系变化、态度转变与未来日期。弹窗引用历史依据；有原因的成长、回忆或计划可明确说明，草稿不会因提醒被丢弃。这是可解释的规则检查，不能保证发现所有自然语言剧情矛盾。

服务端验证器密钥使用 AES-GCM 加密，优先使用 `WORKSPACE_MFA_KEY`，未设置时派生自服务端现有密钥。轮换服务端密钥前必须先迁移加密种子或安排恢复码重新绑定，不能直接轮换后丢弃旧密钥。服务器 MFA 原子事务仅允许 service_role 调用，公开浏览器无法调用。数据库迁移历史保留，以便恢复和审计。
